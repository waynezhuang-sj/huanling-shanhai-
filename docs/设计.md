## 一、核心机制改造:从「抓宠」到「灵契召唤」

| | 宝可梦 | **本作** |
|---|---|---|
| 收服道具 | 宝贝球 | **无道具**,直接结灵契 |
| 携带方式 | 装在球里随身带 | **神兽归位,战时可召唤** |
| 出战 | 放出来 | **召唤**,有召唤动画 |
| 队伍 | 6 只 | **2 只灵契槽位** |
| 地图跟随 | 有的会跟随 | **不跟随**(省地图 sprite) |

**世界观一句话**:你不是「训练师」,你是「**唤灵者**」—— 与山海神兽结契,战时召唤它们降临。

### 这个改动省掉了多少美术

| 原本要画 | 现在 |
|---|---|
| 3 只 × 正/背 两张战斗图 | **3 张**(单张,翻转即可) |
| 3 只 × 地图跟随 sprite | **0 张** |
| 宝贝球图标 + 开合动画 | **0 张** |
| 背包里的怪物图标 | **0 张** |
| **合计** | **从 15+ 张降到 3 张** |

## 三、存档:本地 + 存档码(双保险)

GitHub Pages 是静态站,每台设备的 `localStorage` 互相独立 —— **手机玩的档,电脑打不开**。所以:

### ① 自动存档(本地)
- 每次进城、战斗结束、结契后**自动写入 localStorage**
- 3 个存档位,进游戏时选

### ② 存档码(跨设备)
- 菜单里点「**导出存档码**」→ 生成一串 Base64(约 200-400 字符)
- 复制到微信/备忘录保存
- 换设备后点「**导入存档码**」→ 粘贴恢复

```
示例:SHY1-eyJwb3MiOlsxMCw4XSwicGFydHkiOlt7ImlkIjoibHVzaHUiLCJsdiI6N31dLC...
```

**为什么用存档码而不是云存档:**
- 不需要后端、不需要登录、不花钱
- 复古感契合像素游戏(就是老游戏的「密码续关」)
- 缺点:得自己保存那串码 —— 所以我会在导出时提示"复制到备忘录"

> 后续要真云存档,可接 GitHub Gist + 个人 token,但那属于 v2 的事。

## 四、命名候选(要流行,不要"异闻录"这种土味)

| 候选 | 感觉 | 与机制咬合度 |
|---|---|---|
| **《山海纪行》** | 徐霞客游记味,"纪行"=旅行记,文气但不酸 | 中 |
| **《唤灵山海》** | 直接点出「召唤神兽」核心玩法 | **高** ⭐ |
| **《踏山海》** | 动词开头,利落有动作感,适合短视频传播 | 中 |
| **《山海游》** | 最短最好记,但略平 | 中 |

**我推荐《唤灵山海》** —— 因为它把玩法(唤灵)写进名字里,玩家看一眼就知道是什么游戏,而且"唤灵"比"抓宠"更高级,契合神兽设定。

**备选**:如果更想要"游记"的感觉,选《山海纪行》。
