## 索引和文档冲突处理

tiles 和神兽严格使用任务文档给定顺序。神兽顺序为鹿蜀、赤鱬、讙、石魅；NPC 顺序为 healer、merchant、villager。

任务文档第二节要求 hero 为 **4 列×3 行**，manifest 示例也要求 `cols: 4`；但其 `layout` 字符串要求“四个方向各占一行，每行三帧”，这需要 3 列×4 行，无法同时满足。本交付优先遵守明确的尺寸与 cols 字段，保留 4 列×3 行，并修正 manifest 的 layout 为真实物理布局。连续语义帧如下：

| 方向 | 帧索引 | 各帧姿态 |
| --- | --- | --- |
| 下 | 0, 1, 2 | 站立、左步、右步 |
| 左 | 3, 4, 5 | 站立、左步、右步 |
| 右 | 6, 7, 8 | 站立、左步、右步 |
| 上 | 9, 10, 11 | 站立、左步、右步 |

所有图集按从零开始的行优先索引：`x = (index % cols) * frameW`，`y = floor(index / cols) * frameH`。方向组可能跨越物理行；manifest 的 `directions` 和逐帧 `names` 明确表达映射，代码接线时应据此读取。本任务未修改代码来接线。

## UI 矩形

矩形为 `[x, y, width, height]`，相互不重叠。dialog 为 `[0,0,96,48]`，button 为 `[104,0,64,24]`，hpBack 为 `[104,32,80,12]`，hpFill 为 `[108,52,72,4]`，joystickBase 为 `[0,64,48,48]`，joystickThumb 为 `[56,76,24,24]`。dialog/button 九宫格四边各 3px；血条填充绘制在血条底局部偏移 `[4,4]`，填充原图独立存储以避免相互污染。

## 来源、生成与验收

场景图块来自 Kenney Tiny Town（CC0），人物头部基础来自 Tiny Dungeon（CC0），UI 来自 Pixel Adventure（CC0）。缺失的帧、形象和部件使用 PIL 补画；新增图片部分以 CC0 发布，逐项链接及原包编号见 `public/assets/mvp/CREDITS.md`。

全部游戏素材采用同一 15 色不透明调色板，连同透明色最多 16 色；神兽有深色描边、各自不同的轮廓和至少 4px 的透明边距。禁止插值模糊，建议以最近邻方式使用。

在仓库根目录执行：

```sh
python3 public/assets/mvp/_generate.py
python3 public/assets/mvp/_verify.py
```

已在 Pillow 12.3.0 下生成与验证；运行无需下载素材，直接读取 sources 内保留的官方原包。校验会实际打开全部 6 个 PNG，核对指定尺寸、网格、52 个有效精灵帧和 6 个 UI 部件的 alpha 覆盖率（>5%）、空白补位、颜色数、语义索引、神兽所有两两像素差异（以整帧 4096 像素为分母，>10%）、透明边距、描边色、主角首帧方向差异和同方向步态差异。
